# 0.7.0 规划：待处理、待审阅与本轮改动

状态：0.7.0 已按本规划实现，验证结果见 VERIFICATION.md。以下保留约定范围。

M0 实证决定：官方 JSONL 保存 FileChange 文件级补丁，与实时文件项可归一化为相同证据；首版统一展示逐次操作，不依赖仅在实时流里的聚合 diff。回合目录使用该轮记录 cwd。代码缓存为实时补丁及预览各 8 MiB，合计 16 MiB。

## 1. 这一版要解决什么

用户在一个包含多个项目的大工作区里指挥多个 Codex 会话，并在 VS Code 中审计代码。面板应帮助用户完成三个动作：

1. 找出正在等自己处理的会话，直接切到官方侧栏。
2. 找出已经产生新结果、但还没有审阅的回合。
3. 查看能明确归属于该回合的补丁，跳到实际文件检查，再标记已审阅。

完整路径：会话运行 → 需要介入时进入待处理 → 本轮结束进入待审阅 → 查看回复或补丁 → 明确标记已审阅。

“已打开”只表示导航过，“已审阅”表示用户明确确认；二者不能合并。“本轮结束”不等于整个开发任务完成。

## 2. 范围与优先级

### 0.7.0 必做

- 全部、进行中、待处理、待审阅四个筛选及会话数量。
- 跳转下一条待处理会话，继续使用官方侧栏。
- 按回合识别新结果，持久化待审阅／已审阅标记。
- 选择待审阅回合、查看该回合已记录补丁、跳转当前文件。
- 断线、记录缺损、补丁缺失等情况的明确反馈。
- 现有窗口级 Profile、默认只读模式、显式实时监听、Token 同列与独立轮次列保持。

### 后续候选，不进入本次交付

置顶／临时隐藏、同文件重叠修改提示、最近活动摘要、指定会话通知、独立快速搜索切换框。优先级排在本轮审阅流程之后。

不新增聊天输入框、项目看板、笔记系统、批量发送／停止、自动批准／重试、自动合并、Git 暂存或提交。

## 3. 主表继续保持紧凑

### 顶部

宽面板用分段筛选：`全部 8 / 进行中 3 / 待处理 2 / 待审阅 1`，不再重复显示另一份总会话数。保留监听状态入口、搜索和刷新，增加一个“下一条待处理”图标按钮。

窄面板把分段筛选收进同一个筛选按钮／菜单，不新增一整行工具条，不靠缩小字体挤空间。540px 宽、240px 高仍能操作搜索、筛选、下一条和刷新。

### 会话行

- 状态仍显示正在运行、等待批准、等待输入、空闲或记录结果。
- 标题旁使用小型 `待审阅 · 2` 标记，数字指这条会话的待审阅回合数。
- 审阅入口使用 Lucide 图标；宽屏悬停或键盘聚焦显示，窄屏保留可点击目标。
- 不增加统计列；Token 用量和会话轮次继续常驻。
- 点击标题或普通单元格仍切换官方侧栏；审阅按钮阻止事件冒泡，不同时触发聊天切换。
- 状态原地更新，不因状态变化持续重排用户正在看的行。进入某个筛选时确定顺序；新增条目按规则插入，已有行保持相对顺序。

### 筛选口径

| 筛选 | 包含哪些会话 |
| --- | --- |
| 全部 | 当前工作区范围内的交互会话，沿用真实 cwd 边界 |
| 进行中 | 有有效实时观测的运行、等待批准、等待输入、同时等待；不包含 idle、断线或仅有未结束记录 |
| 待处理 | 有效实时等待，或纳入跟踪后的最新失败回合尚未查看 |
| 待审阅 | 至少有一个待审阅回合；即使下一轮已经运行也保留 |

顶部计数按会话去重，不是请求条数或回合数。筛选允许交叉：等待输入属于进行中和待处理；失败且留下已记录补丁，可以同时属于待处理和待审阅。搜索作用于当前筛选；计数保持工作区总览，搜索结果另显示“匹配 n 条”。

## 4. 待处理队列

### 进入与退出

- `waitingOnApproval`／`waitingOnUserInput` 为依据；等待结束即退出，不能靠点击行取消真实等待。
- 重复状态通知不重置等待起点；批准与输入之间切换时，整个连续等待区间仍从首次观测时算起。
- 最新新回合失败后进入待处理。用户成功打开对应官方会话后，只把该失败提醒标为已查看；状态列仍保留失败结果。
- 明确开始下一轮时，上一轮失败不再占据“需要现在处理”的队列；历史结果和未审阅补丁仍保留。
- 后端异常与监听断开作为连接／状态异常显示，不伪装成某一轮执行失败。

### 下一条待处理

1. 范围是当前工作区内的完整待处理队列，不受临时搜索词限制。
2. 实时等待优先于失败提醒；等待按首次观测时间从早到晚排列，批准和输入不人为分高低。
3. 多条时跳过当前选中的会话并循环；仅一条时聚焦该会话。
4. 执行命令后切换到“待处理”筛选、清空临时搜索、定位目标行，再调用现有窗口绑定导航。
5. 导航失败不更新已查看标记；没有目标时提供简短状态反馈，不打开空聊天。

提供命令面板入口和可由用户绑定的快捷键。第一版不抢占 VS Code 的原生标签切换快捷键。

### 失联与覆盖范围

失去有效监听后清除对应实时等待项，不能用旧事件持续宣称“正在等待”。已确认的失败和审阅记录不清除。

待处理视图在监听不可用时说明“实时等待状态不可用”，不能把队列为空写成“所有会话都已处理”。只有文件来源的会话可以产生已记录失败／审阅标记，不能推断实时等待。

## 5. 待审阅按回合，而不是按会话布尔值

### 建立跟踪基线

- 每个工作区、每个规范化 CODEX_HOME 独立建立基线。
- 首次成功索引时，已有明确终态回合记录为历史基线，不把所有旧聊天突然标成待审阅，也不称它们“已审阅”。
- 基线中尚未结束的回合，后来得到明确结束时应正常产生新结果。
- 首次索引不完整时，受影响记录不提交完成基线，避免永久漏掉结果。
- 从后续文件追加或实时事件发现的新终态按同一身份合并；不要求用户当时打开了面板。
- 分叉继承的历史不作为新结果重复提醒。无法可靠划分继承边界时，只把明确新观察到的回合纳入新结果，并标明历史范围未确认。

### 终态规则

| 情况 | 待处理 | 待审阅 |
| --- | --- | --- |
| 新回合正常结束 | 否 | 是，包括只有文字回复的回合 |
| 新回合失败，无已记录补丁 | 未查看时是 | 否；可进入官方会话检查失败 |
| 新回合失败，有已记录补丁 | 未查看时是 | 是，提示结果失败但存在改动 |
| 新回合中断，有已记录补丁 | 否 | 是，提示结果中断 |
| 新回合中断，无已记录补丁 | 否 | 不自动加入 |
| 只有 idle，没有可靠回合 ID／终态 | 不据此生成 | 不据此生成 |

“没有已记录补丁”不等于工作区没有发生文件变化。晚到的补丁证据可以让失败／中断回合进入待审阅。

### 用户操作

- 点击会话：只更新已打开／失败提醒已查看，不改变审阅结论。
- 点击审阅入口：默认选择最早的待审阅回合，提供回合选择器切换；不得只暴露最新一轮而遗失旧轮次。
- “标记本轮已审阅”必须绑定明确的回合 ID 和证据版本；提供撤销为待审阅。
- 一次只确认所选回合，第一版不提供“一键全部已审阅”。
- 审阅旧回合时产生新回合，新结果独立入队；旧视图不自动跳到新回合。
- 已审阅回合后来收到不同的补丁内容，则标记“审阅后有更新”并重新进入待审阅。重复内容不重新提醒。
- 无补丁／仅文字结果时保留“打开官方会话”和明确的“标记已审阅”。当前官方导航只能切会话，不能承诺定位到某一历史回合；详情提供结束时间和回合标识辅助查找。

## 6. 本轮改动查看：先做可信的只读补丁

### 为什么不直接套用整个工作区的 Git diff

一个文件可能被其他会话或用户手工修改。`HEAD → 当前工作区` 不是某条会话开始与结束之间的差异；只有 unified diff 也不能恢复完整的原始文件。

首版明确采用：**选择回合 → 已记录文件清单 → VS Code 只读补丁预览 → 跳转当前文件。**

不虚构完整 before／after 文件，不从当前文件倒推历史基线。具备可信原始快照后再考虑完整双栏差异，不作为 0.7.0 默认能力。

### 交互

- 审阅按钮在底部面板内打开轻量详情，带“返回列表”；不创建第二个 Webview 面板或聊天标签。
- 详情头部显示会话标题、所选回合、结束结果、证据可用情况和“标记本轮已审阅”。
- 文件清单显示相对路径及记录的新增／修改／删除；有可靠补丁时显示行数变化。
- 点击文件打开一个只读虚拟 `.diff` 文档，复用 preview 标签，不移动既有代码编辑器组。用户主动固定的标签按 VS Code 原生行为保留。
- “打开当前文件”是独立动作，不把当前文件内容当成该轮结束时的内容。
- 历史行号只是参考；文件后来改变时不保证仍对应相同行。删除文件、缺失文件仍可看补丁，不创建空文件占位。
- 不提供应用补丁、丢弃改动、暂存、提交或自动恢复按钮。

### 数据与完整性

- `turn/diff/updated` 是回合最新聚合快照，覆盖更新，不拼接累加每次通知。
- `item/completed` 的 `fileChange` 提供文件路径、变更种类和执行状态；按 threadId / turnId / itemId 去重。
- 只能归属到有明确 threadId 和 turnId 的证据，不凭最近活动时间把文件分给会话。
- 文件项与聚合 diff 不一致、缺事件或观察从中途开始时标为部分记录；可展示已知补丁，但不标注“完整改动”。
- 命令直接写文件、外部工具修改、其他会话修改可能未覆盖；文案固定使用“本轮已记录改动”。
- 未收到补丁时显示“本轮没有可用补丁记录”，不能写成“本轮未修改文件”。
- 结束事件和最后一个补丁不假定固定到达顺序。审阅确认绑定证据版本，晚到变更重新提示；不靠等待固定几秒来宣称完整。

### 路径与内容安全

路径由协议提供，属于不可信输入。相对路径依照记录 cwd 归一化，处理 macOS 路径别名；打开真实文件前检查规范化路径位于当前工作区，防止 `..`、符号链接或任意 URI 越界。工作区外路径仅作为文本显示并解释无法打开，不自动访问。

补丁通过只读文档展示，不执行、不作为 HTML 插入，也不发送给模型。文件名、标题等仍使用文本节点。

## 7. 数据模型与持久化

### 身份与分层

核心身份：`规范化数据源 + threadId + turnId`。源目录不同，即使 ID 相同也不能合并。

三类状态分开管理：

1. **运行事实**：最新实时状态、当前可识别回合、等待起点；只在有效连接覆盖内成立，断线清空。
2. **回合事实**：明确终态、结束时间、已记录文件、补丁可用性和证据版本；来自文件或实时事件，按身份合并。
3. **用户处理状态**：历史基线、失败提醒是否查看、某回合哪个证据版本已审阅；本地持久化。

不能再用一个会话级 `reviewed: boolean`，也不能用 `selectedId` 代替已审阅。证据身份必须跨重启稳定：保存所审阅补丁的内容指纹用于识别重复快照和后续内容冲突，不保存正文；不能使用重启后从零开始的计数器作为持久化证据版本。

### 存什么、不存什么

- 使用现有 ExtensionContext 的工作区存储保存初始基线、回合 ID、审阅决定和必要时间／证据版本；同一工作区共享选择规则沿用现有产品约定。
- 持久化用户决定成功后才更新已审阅 UI；保存失败保留待审阅，避免用户以为记录已保存。
- 不修改官方记录、标题索引、SQLite 或项目文件；不持久化完整聊天、工具输出或原始通信。
- 默认不新增持久化代码快照。实时补丁仅留有界内存；重启后优先从官方已落盘证据按需恢复。
- 如果目标版本没有保存可恢复的补丁，标记“补丁未保存／已不可用”，保留回合和用户审阅决定，并提供官方会话入口。不用工作区 Git diff 冒充恢复内容。

协议中的补丁事件已确认；JSONL 是否保存了可回读的同等证据，由 M0 核清。若以后要求跨重启完整保留每轮补丁，需要单独设计本地代码缓存及清理规则，再确认隐私与存储范围。

### 有界内容处理

初始预算：每回合补丁不超过 512 KiB，扩展宿主补丁正文缓存预算不超过 16 MiB（按 UTF-8 字节计，不代表整个进程内存）；先淘汰非当前打开的旧内容，用户审阅标记和待审阅计数不能因淘汰消失。超限显示明确原因，不静默截断成“完整补丁”。实现阶段用真实夹具验证这一预算，不为大补丁无限放大通信队列。

Webview 只接收状态和文件清单等摘要，用户打开补丁时由文档 provider 取内容。解析仍在 Worker，主转发路径不等待观察者。能够明确识别的补丁超限只影响该补丁；若无法确定协议帧边界，则沿用观测缺口处理，不能继续宣称状态准确。

## 8. 技术改造位置

| 位置 | 计划职责 |
| --- | --- |
| `live/protocol.ts` | 用明确的 RuntimeEvent 联合类型替换状态专用事件；定义状态、回合终态、文件变更及补丁更新白名单 |
| `live/observer.ts` / `channel.ts` | 后端事件解析、内容与摘要分离、有界传递、断线和代次隔离；不增加后端写入接口 |
| `sessions/rollout.ts` / `records.ts` | 暴露可归属的回合终态与按需历史证据；保持增量读取，避免每次刷新重新扫描正文 |
| 新增 `sessions/workflow.ts` | 待处理、待审阅、基线、重复／乱序合并和用户确认的单一状态归约器 |
| 新增 `sessions/review.ts` | 回合详情、只读补丁文档 provider、路径检查和显式打开文件 |
| `sessions/controller.ts` | 连接数据源、持久化与操作，沿用串行刷新和目录代次隔离 |
| `view.ts` / `webview.ts` / `table.ts` | 筛选、徽标、审阅入口及详情，保留稳定节点、滚动与焦点 |
| `extension.ts` | 注册下一条待处理、打开审阅等命令；保留 Profile 与监听启停入口 |

内部旧的状态专用接口直接替换，不保留两套事件协议或重复缓存。已有命令、Profile 启动条件、默认只读用法继续成立；新审阅能力不能要求旧用户必须开启监听。缺少实时事件的能力按数据来源明确降级。

## 9. 关键异常规则

| 场景 | 行为 |
| --- | --- |
| 重复结束／补丁通知 | 按身份与内容版本合并，只产生一次新结果 |
| 审阅 A 时 B 结束 | A 的内容和确认目标固定；B 独立进入队列 |
| 用户点击后才出现新补丁 | 若改变已确认证据，重新标记待审阅并说明更新 |
| 监听断开 | 实时等待不可用；保留已确认终态与审阅决定 |
| 数据目录切换 | 丢弃旧读取与旧运行态，使用独立源命名空间；不串用审阅标记 |
| 回滚或文件重写 | 重新核对回合；明确移除的回合退出当前队列，不把确认转移给其他轮次；无法确认时标记记录不完整 |
| 归档或删除会话 | 从当前列表移除；不由本扩展删除官方数据或顺带清理用户标记 |
| 补丁丢失、淘汰、过大 | 保留待审阅结果，解释证据不可用，允许打开官方会话；不展示其他会话差异替代 |
| 路径越界、文件被删除 | 拒绝自动打开越界路径；允许查看已持有的补丁文本 |
| 官方版本未知 | 不启用新的实时协议适配，继续可用的本地记录功能 |

## 10. 实施里程碑

所有阶段由实现者负责集成与验收；不要求用户逐文件调度。

### M0：核清证据与退出问题

在下一次实施授权后，以隔离数据和固定响应生成一轮含新增、修改、删除的任务，核对实际事件、重复快照、事件顺序及 JSONL 可回读内容。输出最小夹具和字段映射，先决定补丁回放的真实覆盖范围。

同时复现 0.6.0 已记录的隔离 VS Code 退出残留，区分测试 CDP 连接、退出流程和插件资源清理。责任归实现者；正常退出验收不能由强制清理代替。它不阻塞已知状态上的待处理／审阅开发，但属于交付前需解决或明确定位的质量项。

## 11. 最小验收集合

单元／集成用例以现有测试为基础补充关键状态组合，不为固定文案和每个 UI 元素分别写测试。

1. 一条运行、一条等待批准、一条等待输入：筛选计数正确，“下一条”逐条切换同一个官方侧栏。
2. 同一会话连续结束两轮，打开会话后仍显示两个待审阅；确认第一轮只清除第一轮。
3. 用户看旧轮时新轮完成，详情不跳走，新的徽标正确出现。
4. 正常结束无代码补丁：可审阅回复；失败／中断有补丁：不会漏掉部分改动。
5. 首次基线不灌入全部旧结果；后续追加及关闭期间可恢复的新终态正确入队。
6. 两条会话修改同一文件、用户再手工改文件：各自只读补丁不串用，不拿当前 Git diff 替代历史。
7. 重复／乱序通知、补丁晚到、证据变更后再审阅；断线后无过期等待提示。
8. 大补丁、缺失补丁、删除文件与越界路径：明确反馈，原通信和工作区保持可用。
9. 审阅状态重启恢复；目录切换隔离；保存失败不误显示已审阅。
10. 822×407 和 540×240 中关键操作可用，背景更新不抢焦点，整行导航和审阅按钮互不误触。

## 12. 本次规划依据

- 当前 0.6.0 源码：`live/protocol.ts` 只提取状态／关闭事件；`rollout.ts` 已聚合回合 ID，但尚无用户审阅状态；`view.ts` 目前是单表。
