# 底部 Codex 会话面板

在终端旁打开 **Codex 会话**，点击一行切换官方 Codex 侧栏。输入、输出、缓存、总计 Token 共用一列，会话轮次单独一列；原有代码布局不变。

需要比较会话或查看逐轮明细时，点击工具栏的图表按钮，在编辑区打开 [会话分析](ANALYTICS.md)。行内图表按钮直接打开该会话的详细分析；普通点击仍切换官方侧栏。

## 展示与可读性

保持一张轻原生紧凑列表，行高 44px；标题、状态和审阅入口优先，目录、模型与时间作为辅助信息。普通主题去掉逐行横线，以轻微圆角和柔和底色标识选中行；顶部仅当前筛选有轻底色，数量不再套徽章。Token 列默认及最小宽度为 136px，四项仍在同一列：第一行“入／出”，第二行“缓／总”。使用 12px 字号和等宽数字特性对齐，总计略加强调，不新增统计列。

实时状态采用 Lucide 图标与文字，不使用整块彩色标签；等待与失败以语义色强调，只有确认运行的图标旋转。待审阅入口保留轻量图标和数量。审阅详情把审阅状态独立显示，突出确认按钮，已审阅后的撤销按钮使用次要样式；文件清单区分目录和文件名。

主题与字体跟随 VS Code，无外部字体或装饰图片。窄面板使用筛选下拉框，360px 宽时工具栏仍可操作；表格内部允许横向滚动。鼠标选择不显示整行硬框，键盘导航保留可见焦点；高对比主题保留控件边界，减少动态效果设置关闭过渡及旋转。

## 调整列宽与显示

鼠标靠近表头右侧边界时显示分隔线，拖动调整宽度，双击恢复这一列的默认宽度。拖动热区宽 9px；其他可见列保持原宽，分隔线跟随指针，保存后保留这些固定宽度。表格太宽时在内部横向滚动，面板变宽时可能留白；需要重新自动填充时使用 **恢复默认布局**。

点击“会话”表头旁的 Lucide 列设置图标，或右键任意表头，可勾选显示列。“会话”列不可隐藏，其他列均可选择；Token 列最小 136px，避免四项数值被挤坏。表头设置与拖动不会触发会话切换。

默认布局保留标题、状态、Token 和轮次；面板宽于 600px 显示工作目录，宽于 680px 显示最近轮耗时，宽于 880px 显示记录更新，宽于 1040px 显示模型 / Provider。首次更改勾选，以当时可见的列为起点进入手选模式；原先自动收起的列需另行勾选。手选后不再随宽度自动隐藏列，改用横向滚动。菜单中的 **恢复默认布局** 同时清除手动列宽和显示选择，恢复默认响应式规则。

修改立即生效，无需重载，自动保存到本机当前工作区的 `workspaceState.sessionColumnLayout`。重新创建面板或重开同一工作区时读取保存值，不写入项目文件，不与其他工作区共享。保存失败会提示并恢复上次成功保存的布局；损坏的记录暂用默认布局并显示错误，可显式恢复默认。重置不改变 Profile、审阅决定或会话源记录。

键盘操作：

- Tab 聚焦分隔线，左右方向键每次调整 8px；配合 Shift 每次调整 32px。
- Home 缩到该列最小宽度，End 放大到 4096px；Escape 取消尚未结束的拖动或按键调整。
- 聚焦表头控件后，Shift+F10 或菜单键打开列设置；Tab 在设置内移动，Escape 关闭并返回原控件。

从审阅详情返回列表时，恢复纵向和横向滚动位置。

## 处理与审阅会话

顶部提供 **全部、进行中、待处理、待审阅**。计数按会话去重，搜索作用于当前筛选；窄面板使用同一个下拉控件。进行中包含实时运行和等待，待处理包含实时等待及尚未查看的新失败结果。

**下一条待处理**优先选择首次观测等待时间较早的会话，再选择失败提醒；切换到待处理筛选、清空搜索，并打开官方侧栏。打开失败会话只将提醒标为已查看，不改变真实失败结果，也不清除仍在后端等待的请求。

点击行内文件图标进入审阅详情：

1. 默认选择最早的待审阅回合，也可以切换到其他已结束回合。
2. 查看该轮文件清单，点击文件打开只读 `.diff` 预览；另一个箭头按钮打开当前文件。
3. 检查后点击 **标记已审阅**，需要时可撤销。打开会话、打开补丁均不会自动确认。

正常结束的文字回复也进入待审阅；失败／中断但有已记录补丁的回合同样保留。新回合不会替换当前查看的旧轮，确认一轮不会清掉其他轮次。若所选证据有变化，需“重新读取本轮”后再确认；已审阅内容变化时重新入队。

初次索引的历史终态作为基线，而非已审阅。基线之后产生的新终态会自动识别；已知会话在扩展关闭期间产生、且仍在文件里的结果可在重启时恢复。分叉继承和不完整历史保守处理：旧历史不重复提醒，明确新观测的回合单独跟踪。数据源目录隔离审阅决定，保存失败不显示已审阅。

### 补丁是该轮记录，不是当前工作区的完整改动

目标版本在 `event_msg.item_completed.item.type=FileChange` 中保存文件操作，包含 thread_id、turn_id、item ID、状态和文件级补丁。新增／删除记录保存内容，修改记录保存 unified_diff；可按需恢复，与实时 `item/completed.fileChange` 归一化到同一证据身份。

预览按逐次操作展示，不把同一文件的多次修改拼成伪造的净差异，不用 Git HEAD 或当前代码倒推历史。命令直接写文件可能未覆盖，未见补丁不等于未修改文件。只读预览不应用补丁、不暂存、不提交；真实文件打开前校验规范化路径和符号链接仍位于工作区内。缺失文件仍可看补丁。

每轮正文上限 512 KiB。实时补丁缓存和只读预览缓存各 8 MiB，超限／被淘汰内容提示不可用，审阅标记不丢失。用户决定及内容指纹保存在工作区状态，指纹仅用于绑定审阅版本；不额外持久化聊天或补丁正文。

## 开启实时状态

默认只读取本地记录。要看准确的运行与等待状态：

1. 点击面板顶部的 **本地记录**，或执行 **Codex 会话：配置实时状态监听（当前窗口）**。
2. 确认 **启用实时监听**。如果尚未使用 Profile 启动器，确认框会说明接管启动入口的范围；原有自定义入口被替换前也会明确提示。
3. 等当前任务结束后重载本窗口。连接成功后，顶部显示 **实时监听**。

设置按工作区保存在本机；其他窗口不会自动开启监听。启用不要求选择非默认 Profile，也不会主动重启当前任务。首次安装统一启动器会修改 application 作用域的 `chatgpt.cliExecutable`，其他窗口重载后也经过这个入口，但没有启用监听的窗口仍直接继承标准流。

状态列区分实时事件与本地记录：

| 显示 | 含义与反馈 |
| --- | --- |
| 运行中 | 后端 `active` 且无等待标记；Lucide 图标旋转，遵循减少动态效果设置 |
| 待批准 | 需要在 Codex 侧栏批准操作 |
| 待回复 | 需要在 Codex 侧栏回复问题 |
| 待处理 | 同时等待批准和回复 |
| 空闲 | 后端明确报告 `idle` |
| 异常 | 后端明确报告 `systemError` |
| 已完成／失败／已停止 | 没有实时状态时显示上一轮结果，悬停可查看记录时间 |
| — | 状态或结果不可用，不显示运行图标或警告图标 |

批准和回答仍在官方 Codex 面板操作，本扩展不提供代答按钮。实时状态只覆盖**经过当前窗口被监听后端、且已收到状态事件的会话**；同目录中的 CLI、桌面端和其他窗口不会自动成为实时会话。没有被观测到的会话继续显示记录状态，不会被推断为空闲或运行。

点击顶部 **实时监听** 可关闭。面板立即停止展示实时状态；转发层在任务结束后重载窗口时退出，Profile 选择保留。监听连接断开时清除实时状态并退回本地记录，顶部明确显示 **监听已断开**；等待首次连接时自动重试；连接建立后若断开，结束该旁路，避免旧后端重新抢占新连接。请在任务结束后重载窗口恢复监听。

## 数据来源与通信边界

标题和历史统计只读以下文件：

- `$CODEX_HOME/session_index.jsonl`：会话标题索引。
- `$CODEX_HOME/sessions/**/*.jsonl`：会话元数据、回合与用量。

目录沿用 `codexProfiles.codexHome`，留空使用 `CODEX_HOME` 或 `~/.codex`。面板不修补源文件、不读写 SQLite、不读取凭据文件，也不启动额外的 Codex 后端。未开启监听时，不要求接管启动入口。

开启监听后，已有启动桥接以 `pipe` 原样转发官方插件与其后端的标准输入输出，并保留背压及退出信号。原始字节不按 JSON 重写，不注入 RPC、不过滤响应、不重发请求、不修改批准或用户回答。

JSON 解析和面板通信位于独立 Worker；主转发路径不等待解析或面板接收。Worker 提取已核验的状态、关闭、回合开始／结束及文件变更完成事件，使用后端的 `activeFlags` 判断等待状态，不根据消息正文或工具名称猜测。专用 Unix socket 发送状态、回合摘要及有界文件补丁，没有执行命令的入口，不传聊天正文、命令输出或批准内容。原有窗口配置 socket 仍只提供启动配置。

主线程待解析分块上限 2 MiB，超限停止旁路，继续转发官方流；Worker 单行上限 1 MiB、状态摘要最多 4096 条。可识别为文件补丁的超长行仅跳过补丁；未知超长／损坏行清空实时状态观测，直到新的明确事件到达；未知状态清除对应会话的实时显示。旁路发送缓冲超限或连接中断不阻塞官方流。索引长期保留摘要和用户审阅标记；补丁正文仅进入有界内存缓存，不落盘通信日志。

转发层仍位于通信路径上：Worker 或面板失败可以独立降级，但桥接进程本身崩溃可能中断官方连接。需要恢复时，在任务结束后关闭监听并重载；若完全停用启动器，使用 **Codex Profiles：停用切换器（所有窗口）**。未知官方版本不启用监听，面板提示未适配。

## 每条会话的统计

| 字段 | 含义 |
| --- | --- |
| 会话 | 标题索引名称；缺失时使用首条用户消息摘要 |
| 工作目录 | 实际 `cwd` 的完整工作区相对路径；根目录显示如 `yhx（根目录）`，多根工作区显示完整路径 |
| 模型 / Provider | 最近落盘的配置，不是实时请求遥测 |
| Token 用量 | 同一单元格用入／出／缓／总显示输入、输出、缓存输入、总计；各项缺失独立显示 `—` |
| 会话轮次 | 按 `turn_id` 去重，包含尚无结果的回合；不是消息条数 |
| 最近轮耗时 | 最新记录回合的 `duration_ms`，无耗时记录显示 `—` |
| 记录更新 | 本地会话记录及标题索引更新时间，不表示实时事件时间 |

主表数字保留最多三位有效数字，K / M / B / T 分别表示千、百万、十亿、万亿，例如 `110K`、`18.4K`、`128K`。标签悬停解释含义，数值与单元格悬停保留精确整数及完整统计；格式化不修改原始用量。

开启实时状态不会改变 Token 和轮次的统计来源；这些字段仍等官方写入记录后更新。悬停 Token 或耗时可看精确数值、缓存写入、推理输出、回合结果分布、已记录执行时长和有耗时的回合数。

累计 Token 使用覆盖更新的快照，不累加重复事件。缓存输入属于输入、推理输出属于输出，不再计入总量。时间只累加明确记录的毫秒耗时，不使用闲置时间凑数。分析页的跨会话汇总排除带继承历史的分叉会话，单会话明细仍保留原始统计。

缺失显示 `—`，明确的零才显示 `0`。历史损坏、缺少回合 ID 或回滚时，不提供假精确总轮次；后续明确结束事件仍可更新最近结果和耗时。暂不展示上下文占用百分比。

## 自动刷新与交互

- 文件新增、变化、删除合并约 750 毫秒刷新；每 15 秒另做检查。
- 实时事件立即更新状态及回合信息，同时合并一次记录刷新。
- 从终端等标签切回会话面板时立即重新读取；无需手动点击刷新。
- 同时只有一轮读取，重复请求合并；切换配置目录或工作区后，旧任务和旧错误不会覆盖新列表。后端配置目录变化后，实时模式提示重载，不把旧后端状态混入新目录。

首次流式索引，之后只读增长部分。文件缩短、inode / device 替换或同尺寸修改时间变化时重建；同一文件变长按追加处理，不额外扫描旧前缀。末尾半行等待下一次写完。归档、删除的文件不再列出；只展示当前工作区内的交互会话，排除已标识的 exec 和子代理日志。

搜索支持标题、相对目录和完整路径。悬停工作目录显示原始 `cwd`。刷新复用行节点、按需重排，保留滚动位置，后台更新不抢编辑器焦点。方向键移动，Enter 切换；`Cmd+Alt+K` / `Ctrl+Alt+K` 打开面板。默认布局在窄面板保留标题、状态、Token 和轮次；手选布局按保存的列显示。

## 版本与实现

实时协议和会话导航适配官方 `openai.chatgpt 26.51021.22027`。导航继续使用 `/local/<会话 ID>` 的窗口绑定 URI，进入官方侧栏，不创建聊天编辑器标签；首次跳转遵循 VS Code URI 确认，不修改允许列表。版本不符时提示实际版本和适配版本，本地统计仍可读取。当前支持受信任的本机 macOS / Linux 工作区。

- `live/protocol.ts` + `events.ts`：事件契约与目标版本的严格解析。
- `live/tap.ts` + `live/observer.ts`：有界复制与独立解析 Worker。
- `live/channel.ts`：窗口内摘要接收、连接生命周期和断线清空。
- `sessions/jsonl.ts` + `rollout.ts`：只读增量扫描与历史统计。
- `sessions/records.ts` + `catalog.ts`：文件缓存、并发和目录筛选。
- `sessions/turns.ts` + `workflow.ts`：文件证据归一化、初始基线、待处理队列与逐轮审阅决定。
- `sessions/review.ts` + `review-view.ts`：只读补丁文档、工作区路径检查与详情视图。
- `sessions/controller.ts`：刷新、数据源隔离、审阅操作与当前工作区导航。
- `sessions/navigation.ts`：官方版本检查及 URI 跳转。
- `sessions/columns.ts` + `column-layout.ts`：共享列定义、布局校验与工作区保存、拖动与键盘调整、列显示设置。
- `sessions/analytics.ts` + `analytics-panel.ts` + `analytics-webview.ts`：统计口径、编辑区单例标签与图表／回合明细联动。
- `sessions/status.ts`：底部面板、分析页和审阅页共用的状态名称。
- `sessions/view.ts` + `webview.ts` + `table.ts`：消息校验、交互和稳定行更新。

验证命令与证据见 `CONTRIBUTING.md`、`VERIFICATION.md`。
