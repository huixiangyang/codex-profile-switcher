# Codex Sessions & Profiles

[English](README.en.md) · [下载安装包](https://github.com/huixiangyang/codex-profile-switcher/releases) · [问题反馈](https://github.com/huixiangyang/codex-profile-switcher/issues)

在 VS Code 底部、终端旁增加一个 **Codex 会话** 面板：汇总会话，筛选待处理与待审阅结果，可选显示实时运行与等待状态，同列显示输入、输出、缓存与总计 Token，单独显示会话轮次和最近轮耗时。点击一行切换官方 Codex 侧栏，代码布局不变。

## 使用会话面板

1. 安装 `0.9.3` VSIX。当前导航及实时状态适配官方 `openai.chatgpt` **26.51021.22027**。
2. 升级后，在当前任务结束时重载窗口。默认使用本地记录，实时监听需要单独确认启用。
3. 点击底部 **Codex 会话**，或按 `Cmd+Alt+K`（Linux：`Ctrl+Alt+K`）。面板直接读取已有记录，不要求选择 Profile 或配置启动器。
4. 搜索标题、工作目录；点击切换会话，悬停 Token 或耗时查看明细。

首次跳转时，VS Code 会询问是否允许 Codex 打开此 URI；可勾选“不再询问此扩展”。扩展不会修改信任允许列表。

界面采用轻原生列表，沿用 VS Code 主题与字体，保持 44px 紧凑行高。普通主题去掉逐行横线和状态色块，用柔和选中底色、轻量筛选与文字层级区分信息；等待与失败保留语义色和图标，审阅详情突出“标记已审阅”操作。键盘焦点、高对比主题和减少动态效果设置均有对应处理。

### 调整列布局

- **调整宽度**：拖动表头右侧分隔线；双击分隔线恢复这一列的默认宽度。拖动不会切换会话。
- **选择显示列**：点击“会话”表头旁的列设置图标，或右键任意表头，勾选需要的列。“会话”列固定保留；Token 列默认及最小宽度均为 136px。
- **自动记住**：修改立即生效，无需重载，并自动保存在本机当前工作区。重新打开后沿用，不改变其他工作区的布局。
- 默认布局随面板宽度收起辅助列；首次更改勾选时，以当前可见列为起点切换为手选模式。**手选的列在窄面板也保持显示**，放不下时横向滚动。手动调整后的宽度保持固定，面板变宽时可能留白。
- 点击 **恢复默认布局**，同时重置列宽和显示选择，恢复响应式布局。只影响布局，不改变会话或审阅状态。

也可用 Tab 聚焦分隔线，再用左右方向键调整；按 Escape 取消尚未结束的调整。完整快捷键见 [会话面板与统计](docs/SESSIONS.md#调整列宽与显示)。

### 在编辑区查看分析

点击底部面板右上角的图表按钮，在平常打开代码文件的编辑区打开 **会话分析**。重复点击复用同一个标签页。也可执行 **Codex 会话：打开会话分析**。

分析页直接进入工具栏和数据：总览以会话表为主、图表置于侧边；详情将用量、耗时图和回合明细并排，完整记录表紧接其后。正文保持 12–13px，不使用大标题配说明的页头。

- **总览**：当前工作区的 Token、缓存命中率、回合与执行耗时，支持搜索、工作目录筛选和会话排序。
- **单会话**：点击总览中的标题，或悬停底部会话行后点击图表按钮。查看用量构成、耗时中位数／P95、逐轮记录。
- **点选回合**：点击耗时柱或记录序号，查看对应结果、时间和文件操作；“审阅本轮”返回底部面板的该轮审阅，“打开 Codex”切换官方侧栏。

统计复用本地记录并自动刷新。缺失值保留 `—`；跨会话汇总排除带继承历史的分叉会话，避免重复计算。详细口径见 [会话分析](docs/ANALYTICS.md)。

### 待处理与逐轮审阅

- 顶部切换 **全部／进行中／待处理／待审阅**；数量按会话计算，各筛选可以交叉。窄面板使用筛选下拉框。
- 点击 **下一条待处理**，优先跳到等待最久的会话，再处理未查看的新失败回合。仍在官方侧栏批准或回答。
- 新结束的回合显示待审阅数量。**打开会话不等于已审阅**；点击行内文件图标，选择具体回合，再明确标记或撤销审阅。
- 只读补丁预览展示本轮记录到的逐次文件操作；不会把工作区 Git diff 混入某个会话。可以单独打开当前文件，工作区外路径会被拒绝。
- 查看旧轮时新轮完成，当前详情不会跳走。已经确认的补丁发生变化会重新提示审阅；首次读取旧会话时，不批量生成提醒。

审阅决定保存在 VS Code 本机工作区状态中。文件级补丁可从已核验的官方 JSONL 记录按需恢复，缺失、过大或损坏的证据会明确提示；不创建新的永久代码快照。只读模式也支持记录来源的失败提醒和审阅；实时等待筛选需要启用监听。

### 单条会话统计

- **Token 用量**：默认及最小宽度为 136px，单列以两行显示“入／出／缓／总”，分别代表输入、输出、缓存输入、总计，四项直接可见。数字采用三位有效数字的 K/M/B/T 紧凑格式，省去多余的 `.0`，字号仍为 12px；“缓存”属于输入。悬停查看精确数值、缓存写入和推理输出。使用最新累计快照，不把缓存或重复快照再次相加。
- **会话轮次**：单独一列，按回合 ID 去重，包含尚无结果的回合；不等于消息条数。记录不足时显示 `—`。
- **最近轮耗时**：只使用明确记录的毫秒耗时。悬停还可查看记录回合数、结束／失败／中断次数、已记录执行时长和有耗时数据的回合数量。
- 缺失数据用 `—`，只有明确记录的零才显示 `0`。分叉继承、损坏记录或历史回滚会在明细中提示。暂不展示上下文占用百分比。

### 实时运行、批准与输入状态

点击面板顶部 **本地记录** → 确认 **启用实时监听** → 任务结束后重载本窗口。也可执行 **Codex 会话：配置实时状态监听（当前窗口）**。

- **运行中**：当前正在执行，图标转圈。
- **待批准／待回复**：需要你在 Codex 侧栏批准或回复；同时等待两种操作时显示 **待处理**。
- **空闲／异常**：显示后端当前状态。断线后停止转圈，可在任务结束后重载恢复连接。

实时监听默认关闭，只覆盖当前窗口已观测的会话。没有实时状态时，显示上一轮的 **已完成／失败／已停止**；拿不到结果则显示 **—**。悬停可查看这是实时状态还是上一轮结果。分析页只有与当前运行回合 ID 匹配的那一轮显示运行或等待状态，不会把旧轮也标成运行中。

首次启用需要接管启动入口，确认框会说明全局入口及当前自定义启动配置的影响；不会自动重启任务。点击 **实时监听** 可关闭，转发层在下次重载退出。Token、轮次和耗时仍读取落盘统计。

历史统计不完整与最近状态分开判断：后续已有明确结束事件时，正常显示结果及该轮耗时；需要完整历史的回合计数仍保留 `—`。

“工作目录”保留实际 `cwd` 的完整相对层级，根目录显示目录名和“根目录”标记，例如 `yhx（根目录）`，多根工作区显示完整路径；悬停查看后端记录的原始路径。模型列表示最近记录的配置。

### 数据如何读取

标题和统计只读 `$CODEX_HOME/session_index.jsonl` 与 `sessions/**/*.jsonl`，不读写 SQLite 或凭据文件。初次流式索引，之后增量读取；文件变化触发刷新，每 15 秒检查一次，切回面板立即读取。数据源沿用 `codexProfiles.codexHome`，默认 `CODEX_HOME` 或 `~/.codex`。

关闭实时监听时，Profile 启动器直接继承标准流。开启后原样转发官方插件与原有后端的字节流，独立 Worker 提取状态、回合及有界文件补丁；不注入请求、不代答批准、不保存聊天或通信日志，不启动额外 Codex 后端。旁路解析或面板连接失败不阻塞原始转发；桥接进程自身崩溃仍可能中断官方连接。

刷新复用会话行、保留滚动位置，不从代码编辑器或官方侧栏抢焦点。切换目录或工作区时取消旧读取，旧结果和错误不会覆盖新列表。原有窗口级 Profile 行为保持独立。

详细说明见 [会话面板与统计](docs/SESSIONS.md)。

## 窗口级 Profile

点击状态栏的 **Codex: profile名称**，选择本机配置，随后使用通知中的 **重新加载窗口** 按钮生效。选择按工作区保存在本机，重新打开项目后恢复。

独立社区项目，采用 MIT 许可，与 OpenAI 无隶属关系。当前为预览版，通过官方扩展的开发用途设置实现切换。

当前版本用于本机 macOS / Linux（arm64、x64），要求 VS Code 1.95.0 或以上。不支持 Windows、WSL、Remote SSH、Dev Container 或浏览器版 VS Code。已在 macOS arm64 上验证后端启动；Linux 尚未做真实 Codex 宿主验收。当前界面文案为中文。

## 安装与使用 Profile

1. 安装官方 Codex 扩展 `openai.chatgpt`。
2. 从 [GitHub Releases](https://github.com/huixiangyang/codex-profile-switcher/releases) 下载 `.vsix`，在命令面板执行 **Extensions: Install from VSIX… / 扩展: 从 VSIX 安装…**，选择安装包。
3. 点击右下角状态栏 **Codex: …**，或执行 **Codex Profiles: 切换 Profile**。
4. 选择 profile，点击 **重新加载窗口**，再新建 Codex 对话。

扩展启动时不会主动改写现有 Codex 设置。已有自定义启动脚本会显示为“外部启动配置”，仅在首次选择 Profile 或确认启用实时监听时接管全局启动入口。此后每个窗口独立选择 profile，切换或恢复默认只需重载当前窗口，不改变其他窗口的选择或后端。新设置不会迁移正在运行的对话。

例如：项目 A 使用 `review`，项目 B 使用 `coding`；在 A 中选择默认配置，B 继续使用 `coding`。首次打开的项目使用默认配置。同一项目按一个窗口使用；不提供同一工作区多窗口的独立持久化选择。空窗口需要先打开文件夹或工作区。

也可通过命令行安装：

```sh
code --install-extension codex-profile-switcher-0.9.3.vsix
```

当前发行渠道为 GitHub Releases，尚未发布至 VS Code Marketplace。

### 从 0.1.0 升级

0.2.0 移除了按 profile 生成全局启动路径的实现。升级后在各项目窗口重新选择一次 profile 并重载；旧全局选择不会自动复制到所有工作区。启动脚本安装后，尚未选择的窗口重载时使用默认配置。

### Profile 文件

扫描 `$CODEX_HOME/*.config.toml`，默认目录为 `~/.codex`。也可以设置 `codexProfiles.codexHome` 指定绝对路径。

例如 `~/.codex/review.config.toml`：

```toml
# 继承 config.toml 中的 provider 和模型，只提高推理强度。
model_reasoning_effort = "high"
```

若要切换已配置的 provider，可加入 `model_provider = "your-provider-id"`。Provider 定义和凭据继续由用户级配置或凭据存储管理。名称只支持字母、数字、短横线和下划线。菜单只展示名称、provider 和模型；无效 TOML 会阻止切换，并提供打开文件入口。缺失的配置目录会显示空列表，不会新建或覆盖用户配置。可直接复制仓库中的 [示例](examples/review.config.toml.example)。

### 命令

| 命令 | 用途 |
| --- | --- |
| Codex Profiles: 切换 Profile | 列出默认配置和发现的 profiles |
| Codex Profiles: 打开当前配置文件 | 编辑所选 profile；默认模式打开 config.toml |
| Codex Profiles: 刷新 Profiles | 检查配置目录并刷新状态栏；切换菜单每次都会重新扫描 |
| Codex Profiles: 当前窗口恢复默认 Profile | 仅当前窗口使用 config.toml，保留其他窗口的选择 |
| Codex Profiles: 停用切换器（所有窗口） | 卸载前清除统一启动入口，确认后对所有窗口生效 |
| Codex Profiles: 修复 Codex 已知问题（所有窗口） | 为已核验版本备份并应用两项定向修复 |
| Codex Profiles: 还原 Codex 官方文件（所有窗口） | 校验备份并还原修复过的文件 |

修改 profile 内容后，需要重载窗口才能用于新启动的 Codex。更改配置目录后，需要重新选择 profile。

`codexProfiles.codexHome` 支持绝对路径或 `~/` 路径，留空时读取 `CODEX_HOME` 或 `~/.codex`。`codexProfiles.showStatusBar` 控制状态栏入口，默认开启。两项设置都支持工作区覆盖。所选 profile 保存在 VS Code 的本机工作区状态中，不写入项目文件。

### Codex 多窗口修复

0.3.0 增加显式修复命令，安装、激活、切换 profile 时均不会自动应用。**结束当前任务后**，执行“修复 Codex 已知问题（所有窗口）”，再重载所有使用 Codex 的窗口。文件属于同一份官方扩展安装，修复范围覆盖这些窗口，不限于当前项目。

当前只接受官方 `openai.chatgpt 26.5928.31416` 的两份已核验文件；版本和完整 SHA-256 必须同时匹配，否则停止。修复直接修改官方扩展文件，包括：

- 释放待发送消息锁时返回有效 JSON，避免前端解析 `undefined`。
- 后台队列仅由会话所属窗口处理；本窗口刚提交的队列头消息仍可按上游规则获取所有权。其他窗口不会自动恢复共享队列里的聊天。主动发送和“立即发送”入口保留原有检查。

这会改变重载后的队列恢复行为：没有所属窗口的历史待发送消息保留在队列中，需要打开对应聊天取得所有权或主动发送。不会删除消息、强制抢锁或关闭后端。

原文件和校验清单保存在扩展全局存储的 `codex-repairs/` 下。全部预检和备份完成后才写入；普通失败会回滚，进程异常中断后的混合状态可重新执行修复或还原。并行窗口使用回环 TCP 监听锁互斥，不通过该端口传输数据；端口已占用时停止操作。目标文件或备份有外部改动时拒绝覆盖。

需要撤销时，执行“还原 Codex 官方文件（所有窗口）”并重载相关窗口。**停用或卸载切换器不会自动还原这些文件**；请先还原，或者重新安装官方 Codex。官方升级后不会自动重打补丁，未知版本必须重新核验。

此修复针对已确认的空响应和跨窗口队列缺陷，**不修复 Electron 原生渲染进程崩溃**。已验证逻辑分支、真实文件副本的语法及逐字节还原；真实 VS Code 多窗口、模型发送和长期稳定性尚未验收。详见 [验证记录](VERIFICATION.md)。

## 实现与边界

官方 Codex 当前没有 profile 选择设置。已验证版本 `26.5908.31748` 的 `app-server` 还会拒绝 `--profile`，`chatgpt.cliExecutable` 仅支持 application 作用域。本扩展将该设置指向固定的统一启动脚本；脚本根据父进程连接所属窗口的本地 Unix socket，取得该窗口的选择，将 profile 转换成 `-c key=value`，然后启动官方扩展配套的 Codex 二进制。默认模式不添加 profile 参数。

- 不修改全局 `config.toml`、profile 原文件或登录凭据。只有显式修复／还原命令会修改已核验的官方扩展代码。
- 使用 VS Code 自身的 Node 运行时，无需另装 Node / Python。
- 参数直接传入，退出信号转交后端；未启用实时监听时标准流直接继承；不记录 profile 正文、完整启动参数或凭据。
- 命令行配置优先级高于项目配置，与 CLI 原生 profile 层级并不完全相同。
- Profile 值会成为本机进程启动参数。因此密钥应留在用户级 provider 配置或凭据存储中，不放进 profile 文件。
- 状态栏显示所选启动配置；“待重载”表示本窗口还未按新选择重载，不代表模型服务已经连通。旧对话可能保留原有 provider。
- 每次宿主启动固定当前选择；只保存新选择不会让本次宿主重启的后端提前切换。
- Codex 后端先启动时，启动器最多等待 15 秒让本窗口的切换器完成激活。找不到所属窗口时明确报错，不使用其他窗口的配置。
- 依赖切换器和官方 Codex 运行在同一扩展宿主。手工配置扩展宿主 affinity 将两者分离时不受支持。
- 各窗口共享所选配置目录中的 Codex 状态库与凭据。已验证官方版本在首次并行初始化同一全新目录时偶有 SQLite 初始化失败；全新目录应先在一个窗口启动成功，再打开其他窗口。
- 官方把 `chatgpt.cliExecutable` 标记为开发用途。后续 Codex 扩展更新可能改变接口，需要重新验证。

统一启动器和原启动路径备份 `previous-startup.json` 保存在该扩展的 VS Code 全局存储目录中。接管时只记录原路径，不复制凭据。窗口通信 socket 放在 `/tmp/codex-profiles-<存储路径哈希>/` 的私有目录中，正常退出时移除 socket。

**若应用过 Codex 修复，先执行“还原 Codex 官方文件（所有窗口）”。卸载或禁用前再执行“停用切换器（所有窗口）”，并重新加载所有相关窗口**，避免 Codex 仍指向本扩展的启动脚本。“当前窗口恢复默认 Profile”只改变当前选择，不会断开启动器。若已经卸载，可从 VS Code 用户设置中删除 `chatgpt.cliExecutable` 后重载；官方文件可通过重新安装 Codex 还原。停用不会恢复接管前的第三方启动脚本；原路径可在 `previous-startup.json` 中查找。

官方资料：[IDE 设置](https://learn.chatgpt.com/docs/developer-settings?surface=ide)、[Profiles](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles)。
